# YouTrade Webapp

Frontend Y.CS на React, Vite и TypeScript: публичный лендинг, документы и вход через Telegram OIDC. После входа кабинет показывает заглушку с переходом в бота; торговые разделы пока не подключены.

Главная страница — публичный лендинг YouTrade.CS. Она загружает агрегированную статистику, актуальные тарифы и расчётные курсы Steam без авторизации. Если один из публичных запросов недоступен, соответствующие динамические данные скрываются, а остальная страница продолжает работать.

## Общая панель и тема

`SiteLayout` держит панель над страницами React Router. Внутренние ссылки
`SiteLink` сохраняют приложение и состояние сессии; экран запуска не появляется
при переходах в кабинет или документы. Восстановление входа обозначается под
панелью и в области профиля. Кабинет пока остаётся заглушкой.

`shared/site/` содержит навигацию, стили и иконки панели, функции темы и
поведение выпадающих меню. React и VitePress используют свои небольшие
компоненты представления. Меню профиля отдельно от навигации и темы.
Навигация привязана к логотипу и не центрируется по оставшемуся месту:
её положение не меняется между гостевым и авторизованным состояниями.
После входа вместо ссылки показывается круглая аватарка либо общая иконка
профиля. Меню открывается наведением, фокусом или нажатием; закрывается
Escape и нажатием вне шапки. Стрелки у аватарки нет.

Кнопки сайта и обучения используют общий `shared/site/buttons.css`:
контрастную заливку для входа, бордовый акцент для основных действий и
прозрачные второстепенные кнопки со скруглённой подложкой при наведении.
Состояния и размеры едины для React и встроенных `VPButton` VitePress,
иконки плеера и панели берутся из общего SVG. Кнопки документов учитывают
светлую подложку, даже если у сайта выбрана тёмная тема. Самостоятельные
страницы ошибок включают общий CSS при сборке и не зависят от JavaScript.
Небольшое выдвижение плиток сохранено с учётом `prefers-reduced-motion`.
Правило для дальнейших изменений:
[«Кнопки веб-интерфейса»](../docs/ux/design-style.md#кнопки-веб-интерфейса).

Общая закреплённая шапка включает строку курсов Steam над навигацией:
65 px на ПК и 61 px на телефоне, из них 20 px — курсы. Движение строки
занимает 60 секунд за цикл, при наведении и в скрытой вкладке приостанавливается;
при `prefers-reduced-motion` отключается. Данные обновляются раз в пять минут
через публичный `/api/web/v1/steam/currency` на текущем origin.
Для учебного домена этот единственный публичный маршрут добавлен в Nginx.
При недоступных данных строка сохраняет высоту и показывает прочерк.

Обучение — отдельное приложение на другом домене. В нём ссылка «Кабинет»
ведёт на основной сайт, где восстанавливается авторизация. Текущий протокол
не предоставляет междоменного чтения сессии; access-токен и refresh учебному
приложению не передаются, дополнительных auth-маршрутов frontend не вызывает.
Никнейм и аватарка основного сайта берутся из отдельного Bearer-запроса
`GET /api/web/v1/user/profile`, а `/auth/me` сохраняет только идентификаторы.
Источник контракта: [web-auth-frontend.md](../docs/external-patches/lis-tm/7/web-auth-frontend.md).
Подписанная ссылка из `avatar.url` используется без изменения query; при
ошибке картинки профиль перечитывается один раз, затем используется иконка.
Перед `urlExpiresAt` ссылка обновляется через профиль; аватарка не определяет
успех авторизации. При 404 профиля предлагается новый вход через Telegram;
прочие ошибки доступности профиля не завершают действующую сессию.
Формы редактирования и загрузки аватарки пока не подключены: кабинет остаётся
заглушкой, этот этап читает профиль для общей шапки.
При переходах между доменами передаётся только тема, публичным параметром
`theme=dark|light`; после применения параметр удаляется из адреса.
На каждом домене тема хранится под одинаковым ключом `ycs-theme`.

## Локальный запуск

Требуется Node.js 20 или новее.

Для проверки с backend запусти из корня репозитория в PowerShell:

```powershell
.\scripts\run-webapp.ps1
```

Скрипт проверяет JSON ленты на `https://youtradecs.xyz`, подключает Vite к этому
backend и запускает страницу входа на `http://127.0.0.1:5173/auth`.
Если лента недоступна, скрипт выводит предупреждение и запускает сайт.
Для работы с локальным lis-tm передай `-BackendUrl http://127.0.0.1:21488`.
Свободный порт frontend можно задать через `-Port 5174`.

При запуске через скрипт или `npm run dev` запросы `/api` идут через Vite.
В Network отображается адрес страницы. Фактический backend и статус ответа
видны в строках `[api]` в терминале. Без скрипта адрес backend можно задать
через `VITE_DEV_PROXY_TARGET`. `VITE_API_BASE_URL` применяется при сборке сайта.

```bash
npm install
copy .env.example .env
npm run local
```

Для обычного dev-сервера доступна команда `npm run dev`. Проверки: `npm run lint` и `npm run build`.

## Переменные окружения

- `VITE_API_BASE_URL` — адрес публичного API без завершающего `/`. Авторизация и запросы с Bearer всегда используют origin сайта.
- `VITE_TELEGRAM_BOT_USERNAME` — username Telegram-бота для deep link, без `@`.

Секреты, bot token и JWT signing key во frontend не используются. Файл `.env` игнорируется Git.

## Авторизация

Кнопка на `/auth` открывает `/api/web/v1/auth/telegram` навигацией браузера. Backend выполняет OIDC flow и возвращает на `/auth/callback`. Приложение вызывает `POST /api/web/v1/auth/refresh`, сохраняет access только в памяти, получает пользователя через `GET /api/web/v1/auth/me` и его профиль через `GET /api/web/v1/user/profile`, затем открывает `/dashboard`. При первом входе backend создаёт профиль автоматически. Предварительно запускать бота не требуется.

Refresh хранится в серверной HttpOnly Secure SameSite=Strict cookie и восстанавливает вход после перезагрузки. Общая Promise, Web Locks и BroadcastChannel согласуют обновление между запросами и вкладками; актуальные access credentials передаются между вкладками без записи на диск. Требуется современный браузер с поддержкой этих API. После неоднозначного сетевого сбоя refresh не повторяется: пользователь входит заново.

При `401` обычный GET допускает одно обновление и повтор. Изменяющий запрос автоматически не повторяется. Выход вызывает серверный `POST /api/web/v1/auth/logout`, затем очищает локальную сессию во всех открытых вкладках. Другие устройства сохраняют свои сессии. `botLinked` не используется как требование запуска бота.

Контракт и серверные настройки: [патч 7](../docs/external-patches/lis-tm/7/web-auth-frontend.md). Production работает на одном HTTPS-origin; для локального входа необходимо согласовать callback, Origin и cookie с backend, одного изменения URL API недостаточно.

## Возврат после ошибки OAuth

При ожидаемом отказе OAuth backend возвращает браузер на фиксированный адрес
`https://youtradecs.xyz/auth/callback` с публичным кодом в `error`.
[Изменения контрактов патча 7](../docs/external-patches/lis-tm/7/contract-changes.md#авторизация-и-сессии).

При ошибке callback frontend не вызывает refresh и не считает старую сессию
успешным новым входом. Он возвращает на `/auth`, убирает параметр из адреса
и показывает всплывающее уведомление об ошибке. Неизвестный код
получает общий текст; `error_description` и другой текст из URL не выводятся.
Дополнительно поддержаны `access_denied`, `login_expired` и
`temporarily_unavailable`. Успешный callback остаётся без `error`:
та же форма показывает проверку входа, затем открывается `/dashboard`.

Редирект применяется к браузерному OAuth callback. `refresh` и `me`
возвращают ошибки обычными HTTP-статусами.

## Маршруты

Ошибки операций используют общий `useNotifications().error(message, title?)`.
`SiteNotifications` размещён в `SiteLayout` и показывает одно последнее
уведомление под шапкой без изменения компоновки страницы. Уведомление имеет
`role="alert"`, закрывается кнопкой или Escape при фокусе внутри; ошибки
не исчезают по таймеру. Компоненты не должны создавать собственные toast-хосты.
Подключены вход, загрузка документов, сохранение согласия и общий `ErrorState`.
Статические страницы 4xx/5xx продолжают работать без JavaScript.

- `/` — публичный лендинг; использует `GET /api/web/v1/overview` и `GET /api/web/v1/steam/currency`.
- `/auth` — вход через Telegram. Сетка на широком экране показывает до восьми
  карточек из публичного `/api/web/v1/overview/operations`, который возвращает
  до 100 покупок и продаж. Сетка показывает разные предметы. Каждые полторы
  секунды следующая карточка появляется на свободном месте, а уходит одна
  из двух самых дальних доступных карточек. При наведении или фокусе карточка остаётся на месте
  и показывает кнопку копирования названия. Запрос обновляется раз в 30 секунд
  в видимой вкладке. HTTP-кэш браузера выполняет
  перепроверку по ETag. При сбое лента сохраняет последние полученные операции.
  Формат ленты и порядок выкладки описаны в [патче 7](../docs/external-patches/lis-tm/7/landing-api.md#последние-операции-ycs).
- `/auth/callback` — восстановление сессии после серверного callback.
- `/dashboard` — защищённая заглушка будущего кабинета, переход в бота и выход.
- Старые `/connect-bot`, `/accounts`, `/portfolio`, `/parameters`, `/dictionaries`, `/home` перенаправляют в кабинет.

Заглушка не запрашивает баланс, аккаунты или предметы. Старые компоненты торговых разделов остаются в исходниках, но не подключены к маршрутам приложения. При их дальнейшей реализации потребуются соответствующие web-контракты; внутренние Telegram API и сервисные ключи в браузере использовать нельзя.

## Историческая инвентаризация Telegram-контрактов

- `GET /api/telegram/user/general/info` — общая информация и баланс.
- `GET /api/telegram/user/accounts/v2` — аккаунты с пагинацией.
- `GET /api/telegram/user/params/all` — наборы параметров.
- `GET /api/telegram/user/v2/inventory` — инвентарь.
- `GET /api/telegram/user/v2/selling` — выставленные позиции.
- `GET /api/telegram/user/sell/history/buy`, `/history/sell`, `/waiting` — история и ожидание.
- `GET /api/telegram/user/buy/words/included`, `/excluded` — словари.

Эти пути перечислены для ориентира по существующему Telegram-клиенту. Авторизованный кабинет их не вызывает.

Прежний список [TODO_BACKEND_ENDPOINTS.md](./TODO_BACKEND_ENDPOINTS.md) требует повторной сверки перед разработкой торговых разделов. Для авторизации актуален патч 7.

## Проверка авторизации

Браузерные сценарии с локальной имитацией backend: [инструкция](../postman/simulations/README.md). Они проверяют frontend, включая параллельные вкладки и потерю ответа refresh; реальный вход через Telegram необходимо отдельно проверить на настроенном HTTPS-origin.

Для отдельной проверки запуска и кэша после сборки:
`node webapp/scripts/check-startup.mjs` из корня репозитория. Требуется
Playwright с Chromium, переменные его путей те же, что для проверки авторизации.
