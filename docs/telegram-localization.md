# Локализация Telegram-бота

## Что работает сейчас

Используется стандартный Java `ResourceBundle` для чтения словарей и
**ICU4J 78.3** для именованных параметров и языковых форм количества.
Общий Spring-сервис — `BotTexts`, объект текстов выбранного набора —
`LocalizedTexts`. Сервис не хранит текущий язык общим полем.

Подключён весь интерфейс бота: меню, формы, проверки ввода, результаты,
кнопки, уведомления, общие блоки аккаунтов и параметров, Excel-таблицы.

| Раздел | Словари |
|---|---|
| Приветствие, язык и команды | `notification/YTWelcomeMessage`, `preferences/UserLanguage`, `common/Commands` |
| Главное меню и настройки | `start/`, `preferences/` |
| Аккаунты, подключение, сведения и заморозка | `accounts/`, `accounts/add/` |
| Сбор, вывод и продажа баланса | `accounts/money-collect/`, `accounts/money-send/`, `accounts/money-sell/` |
| Параметры, торговля, оценка и следование | `parameters/`, `summary/` |
| Портфель и Excel | `portfolio/`, `table/` |
| Пополнение и реферальная программа | `topup/`, `referral/` |
| Уведомления | `notification/` |

Welcome остаётся отдельным уведомлением и не заменяет `/start`.
Его русское оформление сохранено: `WONDER`, `GLOBE`, цитаты, английская
подсказка и обе кнопки. Английская версия использует ту же композицию.

Выбор `/language` сохраняется прежним вызовом backend. После успешного ответа
меню показывает новый язык, а описания команд обновляются для этого чата.
Если Telegram не принял обновление описаний, сохранённый выбор не откатывается
и успех сохранения не превращается в сообщение об ошибке. Ограничения команд
для заблокированных и неквалифицированных пользователей сохранены.

Общие блоки и генераторы получают `LocalizedTexts` явным аргументом.
Для уведомлений используется сохранённый язык получателя. Сообщения участнику
следования и администраторам о пополнении также формируются для каждого
получателя отдельно.

[Оглавление словарей](../telegram-bot/src/main/resources/i18n/README.md)
показывает наборы по разделам и количество ключей.

## Где оформлять меню

Оформление остаётся в существующем State:

```java
var text = texts.forUser(user, "notification.YTWelcomeMessage");
return String.format("""
        %s <i>%s</i>

        %s <b>%s</b>
        <blockquote>%s</blockquote>
        """,
        DynamicEmoji.YOUTRADE.getEmoji(), text.get("service"),
        DynamicEmoji.BLINK_SMILE.getEmoji(), text.get("title"),
        text.get("introduction"));
```

Здесь видно HTML, пустые строки, расположение блоков и эмодзи. Можно менять
композицию сообщения в одном Java-классе. Русские и английские State не нужны,
ветки `if (russian)` не нужны. Один класс по-прежнему отвечает за один экран.

Подключение выполняется точечными изменениями существующего кода: зависимость
`BotTexts`, выбор набора для пользователя и замена подписей/фраз. Сохраняются
существующие текстблоки, отступы, концы строк, переходы и обработка API.
Пересоздавать классы или массово форматировать их при подключении не нужно.

В словарях подключённых экранов находятся только переводимые заголовки,
подписи и цельные фразы. Переносы строк и технические разделители, включая
`→`, задаются в Java. Символ `™` остаётся в словаре рядом с названием продукта.
Например:

```properties
# YTWelcomeMessage_ru.properties
title=Добро пожаловать в Y.CS
getting-started.title=Первые шаги
getting-started.description=В {tutorial} — подключение аккаунтов, настройка и запуск торговли.
tutorial.link=туториале
tutorial.button=Туториал
```

```properties
# YTWelcomeMessage_en.properties
title=Welcome to Y.CS
getting-started.title=First steps
getting-started.description=The {tutorial} covers account setup, configuration and starting trading.
tutorial.link=tutorial
tutorial.button=Tutorial
```

Порядок слов может различаться, поэтому предложение переводится целиком.
Нельзя получать его склейкой отдельных переводов «В», «туториале» и «—».
`tutorial.link` и `tutorial.button` разделены по смыслу: внутри русской фразы
нужен предложный падеж, на кнопке — именительный.

## Параметры и оформление внутри фразы

`get(key)` возвращает строку без параметров. `format(key, arguments)` использует
именованные аргументы ICU, а не числовые `{0}`, `{1}`:

```java
String tutorial = String.format("<a href=\"%s\">%s</a>",
        DOCUMENTATION_LINK, text.get("tutorial.link"));
String description = text.format("getting-started.description", Map.of("tutorial", tutorial));
```

Ссылка оформляется в State и передаётся целым аргументом. Так перевод может
переставить её внутри предложения, а HTML и URL остаются в Java.

ICU не экранирует HTML. Имена, адреса, причины ошибок и другие внешние
значения нужно экранировать перед вставкой в HTML. Готовый доверенный
HTML-фрагмент, собранный в State, повторно не экранируется. В примере
используются постоянная ссылка и текст из словаря.

Для денежных сумм, процентов, ID и дат передавать заранее отформатированные
строки, сохраняя точность и обозначение валюты конкретного сценария. Числа
в ICU нужны там, где он выбирает форму количества, например число дней.
Это не меняет расчёт прибыльности или представление процентов в Excel.

`String.format` остаётся для оформления Java-текстблока. Для текста с
именованными аргументами используется только `LocalizedTexts.format`.

## Формы количества

ICU выбирает формы по языку. Например, результат установки паузы покупок:

```properties
# ru
purchases-paused-for=Покупки приостановлены на {days, plural, one {# день} few {# дня} many {# дней} other {# дня}}
```

```properties
# en
purchases-paused-for=Purchases paused for {days, plural, one {# day} other {# days}}
```

Вызов `text.format("purchases-paused-for", Map.of("days", 22))` даёт русское «22 дня»
или английское «22 days». Русские 11–14 также обрабатываются правилами ICU.
Такая фраза подключена в `PurchaseFreezePeriodState`: Java передаёт число,
а словарь выбирает форму. Эмодзи успеха и жирное выделение остаются в State.

## Кнопки

Значок и расположение остаются в enum меню, переводится подпись.
Базовые `YTPTextMenuState`, `YTPDocMenuState` и `YTPImageMenuState` передают
переводы через существующий `getTextFunctions`. `BotTexts.buttons(options)`
сопоставляет enum со словарём через `MenuTextBundles`, читает `button.CONSTANT`
и заменяет только исходную подпись, сохраняя значок из Java. Неизменяемые
числовые подписи и бренды не требуют словаря.

Если экран переопределяет динамические подписи, он дополняет результат
`super.getTextFunctions(user)`, как в меню аккаунтов. Для нового enum с
переводимыми кнопками нужно добавить соответствие в `MenuTextBundles` и
парные ключи `button.CONSTANT`.

`optionName`, callback-данные, `rowNum`, URL, стили и видимость от языка
не зависят. `Русский` / `English` — самоназвания языков, они остаются в enum.
`🌐 Language` и английская подсказка в welcome остаются постоянными, чтобы
пользователь мог найти выбор языка, даже если не понимает текущий интерфейс.

## Язык и fallback

`BotTexts.forUser(user, bundle)` использует `user.effectiveLanguage()`.
Для явного выбора есть `forLanguage(UserLanguage, bundle)`, а для общего блока
— `LocalizedTexts.inBundle(bundle)`, сохраняющий исходный язык пользователя:
пользователя в DTO переносить не нужно. Язык ОС, глобальный переключатель
и `ThreadLocal` не используются. Параллельные пользователи имеют свой
языковой контекст, содержимое enum при этом не меняется.

Если в русском файле нет ключа или самого файла, берётся английская версия.
Для неё используются английские правила склонения: `21 days`, а не `21 day`.
Если отсутствует и английский ключ, возникает `MissingResourceException`;
отсутствующие аргументы дают `IllegalArgumentException`. Технический ключ
не отправляется пользователю как будто это готовый текст.

Java кэширует сами ResourceBundle. Форматтер ICU создаётся на вызов, поскольку
его нельзя разделять между потоками без защиты. Параметры не сохраняются
в singleton и не попадают в сообщение другого пользователя.

## Файлы и добавление новых экранов

Файлы UTF-8 называются по существующим меню, например
`preferences/UserLanguage_ru.properties` и `_en.properties`.
Сервис получает basename `preferences.UserLanguage`. Это обычные Java bundles:
103 имени не требуется вручную перечислять в конфигурации Spring.
Ключи короткие и принадлежат своему набору: `title` допустим в разных файлах.

Для нового подключаемого экрана:

1. Создать пару словарей рядом с ближайшим аналогом меню.
2. Оставить HTML и эмодзи в State, сделать парные словари только с текстом.
3. Передать `BotTexts` через конструктор, получить набор для текущего пользователя.
4. Подключить подписи кнопок через enum и `getTextFunctions`.
5. Проверить русскую композицию и английские фразы, переходы и ввод данных.

Все наборы в оглавлении подключены. Старые HTML-шаблоны и числовые
аргументы `java.text.MessageFormat` из словарей удалены. В ICU обычный апостроф
вне синтаксиса аргументов поддерживается; не нужно механически удваивать
апострофы в переводах.

`YTTextNotifier.getText(UserData, D)` получает язык через `notify(user, data)`.
Общие DTO не хранят пользователя или глобальный язык: им передают
`LocalizedTexts`. `enumText(value, field)` читает описания и подписи значений
enum по ключу `EnumClass.CONSTANT.field`; технические имена полей сохраняются.

## Excel

`ITableGenerator.createFile` / `handleFile` и генератор последних предметов
получают `LocalizedTexts` явно. Переводятся заголовки, названия общих вкладок
и подписи отчёта; введённые пользователем имена аккаунтов и предметов остаются
исходными. Даты, числовые значения, индексы столбцов и расчёты не меняются.
Определение ширины и формата колонок учитывает русские и английские подписи.

Проценты остаются числовыми значениями с обычным Excel-форматом процентов.
Загрузка витрины пропускает общую информационную вкладку на обоих языках:
можно скачать файл на RU, переключить язык на EN и загрузить его обратно.
Информационная вкладка остаётся защищённой, редактируемые колонки аккаунтов
и правила чтения значений сохраняются.

Произвольные серверные `cause` и тексты условий не переводятся этим сервисом.
Для известных кодов выбирается локальная фраза. Динамические тексты backend,
названия предметов и пользовательские данные не становятся переводами
автоматически: там, где они выводились, они сохраняются в исходном виде. Внешние
проекты в этой работе не изменялись.

## Терминология

| Русский | English |
|---|---|
| Аккаунт | Account |
| Баланс сервиса | Y.CS balance |
| Реферальный баланс | Referral balance |
| Капитал / банк | Capital / trading capital |
| Оборот | Trading volume |
| Витрина | Listings |
| Ожидание | Pending |
| История покупок / продаж | Purchase history / Sales history |
| Собрать / Вывести / Продать | Collect / Withdraw / Sell |
| Защитный / платёжный пароль | Security / payment password |
| Котировка | Quote |
| К получению | To receive |

Бренды, команды и технические имена полей не переводятся. В пользовательском
тексте используются «аккаунты»; Steam Trade Token остаётся названием реквизита.
Перевод не меняет денежные формулы, валюту или точность.

## Проверки

`mvn -pl telegram-bot -am test` компилирует сервис и выполняет проверки:
именованных аргументов, русских/английских форм количества, обоих вариантов
fallback, отсутствующих ключей и аргументов, параллельных пользователей,
точного сохранения русского welcome, английского welcome и его кнопки,
меню языка, описаний и ограничений команд, обновления после HTTP 204 без тела
и сохранения языка при неудачном обновлении команд Telegram. Проверяются
также точное сохранение русского `/start`, настроек и формы пароля,
английские результаты формы, бонусные блоки и ограниченное обслуживание.
Проверяются все пары словарей, совпадение аргументов RU/EN, отсутствие HTML
и эмодзи в словарях, подписи всех enum меню, описания полей и ссылки инструкций.
Excel-проверки подтверждают точность процентов и загрузку файла витрины после
смены языка.

Это локальные проверки с тестовыми ответами; ручной просмотр в Telegram
и обращения к живому backend в них не выполняются.
