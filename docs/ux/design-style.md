# Стиль интерфейса YouTrade.CS

Дата: 2026-09-17. Зафиксировано по исходникам и существующим графическим ресурсам после прямого указания владельца сохранять его стиль при дальнейшей разработке.

Это описание существующего визуального языка и ориентир для новых экранов. Новые сценарии и расположение действий согласуются отдельно. Предыдущие текстовые схемы реферального кабинета описывали функциональность, а не окончательный дизайн; оформление новых экранов должно следовать этой записке.

## Характер интерфейса

Компактный рабочий интерфейс внутри Telegram: узнаваемая фирменная строка, несколько смысловых блоков с данными, короткая клавиатура. Визуальная выразительность создаётся эмодзи, цитатами, жирными значениями, курсивными пояснениями и символами иерархии. Плотность данных — часть текущего стиля, особенно в истории и списке аккаунтов.

Основной пользователь один раз подключает торговлю, затем добавляет/проверяет аккаунты и смотрит ожидание/историю продаж. Поэтому сохраняем быстрый доступ к данным и привычные компактные представления. Подключённый сервером QuickConfig не требует навязывать пользователю новый мастер.

## Композиция и типографика

1. **Раздел:** обычно `DynamicEmoji.YOUTRADE` + курсивное название, например `<i>Реферальная система</i>`. Сохранять существующее название при локальном расширении экрана. У конкретных действий встречается жирный заголовок вместо курсивного — например пополнение.
2. **Блок:** тематический DynamicEmoji + `<b>Название блока</b>`, затем `<blockquote>` с данными. Между смысловыми блоками одна пустая строка.
3. **Данные:** `• Название: <b>значение</b>`. В профиле для баланса также используется `→`. Не выравнивать столбцы пробелами под одну ширину устройства.
4. **Детали:** `<blockquote expandable>` уже используется для длинных настроек, аккаунтов и подробных уведомлений. Короткую сводку оставлять обычной цитатой.
5. **Пояснения:** `<i>…</i>`, часто строка `└ …`. Инструкции выделяют жирным необходимое действие и объект ввода.
6. **Иерархия:** `┣` и `┗` для состава капитала/строк аккаунтов; `→` для направления торговли; `━━` между парными статусами. Использовать по тому же смыслу, без новых декоративных рамок.
7. **Копируемые значения:** `<code>` для ID, реферального кода, примеров ввода. Не превращать всё сообщение в моноширинный блок.
8. **Скрытые значения:** `<tg-spoiler>` уже применяется к балансу профиля и отдельным данным. Сохранять локальный принцип: в текущей рефералке показатели открыты, в стартовом профиле баланс скрыт. Не прятать все новые суммы автоматически. Spoiler не заменяет маскирование секретов.
9. **Ссылки:** понятное название внутри `<a href="…">…</a>`; для приглашений допустима видимая ссылка как самостоятельный объект копирования/отправки.

HTML — язык существующих шаблонов. При реализации экранировать подставляемые имена, коды и тексты. Нельзя механически копировать некорректную вложенность тегов из отдельных старых сообщений. Полный серверный текст оферты сохраняет содержание и структуру; фирменный стиль применяется к окружающему экрану и навигации.

## Эмодзи и акценты

В тексте использовать существующий `DynamicEmoji`, а не подменять всю систему обычными Unicode-эмодзи. В клавиатурах текущие подписи используют обычный эмодзи и короткий текст.

| Смысл | Существующий элемент |
|---|---|
| Фирменная строка | YOUTRADE |
| Профиль | PROFILE |
| Деньги / капитал / статистика | MONEY / BANK / GRAPH |
| Покупка / продажа / воркер | ITEM_RECEIVE / ITEM_SEND / WORKER |
| Ссылка / подключение / запись | LINK / CONNECT / NOTE |
| Файл / документ | EXCEL или COPY по контексту |
| Выбор / ввод | CHOOSE / WRITE |
| Включено / выключено | ON / OFF |
| Успех / предупреждение / ошибка | SUCCESS / WARNING / ERROR |
| Ожидание | WAIT / CLOCK |

У некоторых custom emoji обычный fallback отличается от предполагаемого визуального символа. Нельзя судить об анимации или фактическом рисунке по fallback. Существующие ID сохранять; для нового элемента сначала искать подходящий в каталоге.

Явный `InlineKeyboardButtonStyle.PRIMARY` найден в двух местах: «Начать торговлю» и «Оплатить». Это редкий акцент на основном действии, а не правило окрашивать каждую кнопку. При добавлении новых финансовых действий ориентироваться на экран оплаты. Семантику ON/OFF не менять попутно с добавлением рефералки или документов.

## Клавиатуры и переходы

- Короткие подписи: «➕ Добавить», «✏️ Сменить имя», «💳 Пополнить», «↩️ Назад».
- Связанные действия объединены строками через `rowNum`: инвентарь/витрина; покупка/продажа; операции с аккаунтами. Не растягивать каждую кнопку на отдельную строку автоматически.
- Длинное или основное действие может занимать отдельную строку, как вход в торговлю и оплата.
- «↩️ Назад» располагается внизу, иногда рядом с переходом между быстрыми и углублёнными настройками. В подтверждении может быть пара подтверждение/отмена.
- Пагинация аккаунтов: `◀️` — текущий режим — `▶️`. Сохранять этот образец для похожих списков.
- Условно видимые кнопки и динамические названия уже являются частью системы. Не показывать недоступное действие только ради симметрии.
- Использовать существующие state/menu/sender механизмы. Точное поведение редактирования сообщений частично реализовано внешней библиотекой; проверить его при реализации, не утверждать, что каждый экран всегда обновляет одно сообщение.

При короткой подписи финансовой кнопки объект действия должен быть однозначно назван в сообщении и подтверждении. Сокращать за счёт окружающего контекста, а не ценой двусмысленности.

## Тон и числа

Внутри интерфейса обращение на «вы»: «Выберите», «Введите», «Теперь отправьте». Названия короткие и предметные: «Профиль», «Финансы», «Капитал», «Статистика». Существуют отдельные рекламные фразы и предупреждения, но новые рабочие экраны следует писать в тоне преобладающих лаконичных инструкций.

Суммы обычно `$35.00`, два знака после разделителя; проценты выделены жирным, точность зависит от показателя. В рефералке уже есть Locale.US и форматирование крупных сумм с разделителями. Сохранить формат раздела; новую денежную арифметику выполнять через BigDecimal. Валюта площадки, баланс сервиса и реферальное вознаграждение обозначаются явно.

Ошибки грамматики, случайные переходы в чужое меню и неточные обещания не являются обязательными признаками авторского стиля. Их исправление не требует менять эмодзи, блоки, тон и композицию всего интерфейса.

## Графические ресурсы и таблицы

Просмотрены `start.png`, `ref.png`, `user.png`, `portfolio.png` в `resources/images/start`. Баннеры разделов 1000×250: небольшой логотип слева сверху, крупное коричневое название слева, светлый фон с переходом в серый справа, предметная иллюстрация справа и точечный силуэт/тень. Названия в просмотренных баннерах преимущественно строчные, шрифт массивный округлый. Точное имя шрифта и код фирменного цвета по исходникам не установлены.

Основные актуальные экраны текстовые. Существование баннеров не является основанием добавлять изображения в каждый новый экран или переносить их коричневый цвет на все Telegram-кнопки.

У XLSX отдельная функциональная палитра из [YouTradeColorCodes](../../telegram-bot/src/main/java/cs/youtrade/autotrade/client/util/YouTradeColorCodes.java): MAIN — голубой фон/тёмно-синий текст, CONTROL — жёлтый/чёрный, SINGLE — светло-зелёный/тёмно-зелёный, GROUP — светло-жёлтый/охристый. Если затрагиваются таблицы, сохранять назначение цветов и существующие генераторы.

## Как применить к ближайшим задачам

**Рефералка:** расширять существующий UserRefState. Сохранить фирменную курсивную строку, блоки показателей/условий кода/подключённого кода. Новые доступный баланс и заработок за всё время оформить строками с жирными суммами в смысловом блоке. Новую ссылку и действия встроить в ту же структуру. Решение о составе показателей — отдельно от оформления; прежние поля не удалять молча ради упрощения макета.

**Перевод:** композиция по UserPayProceedState — название операции, сумма, короткие условия, подтверждение и возврат. Сообщение об успехе по существующим терминальным состояниям: SUCCESS + жирный результат, при необходимости блок обновлённых балансов.

**Документы:** вход отдельной командой, как обсуждалось. Фирменная строка, название документа, версия/статус в небольшом блоке, полный текст доступен для чтения, короткие кнопки чтения/принятия/возврата. Не добавлять документы на основной рабочий экран. Принятие не оформлять как тревогу или блокировку: по текущему контракту оно добровольное.

## Проверка перед завершением UI-изменения

1. У нового экрана есть конкретный существующий образец из таблицы выше.
2. Сохранены DynamicEmoji, иерархия заголовков/цитат/значений и привычный возврат.
3. Подписи и ряды клавиатуры соответствуют соседним экранам; цветовые акценты редкие.
4. Числа и статусы корректны, динамический HTML экранирован; секреты не раскрываются ради копирования старого шаблона.
5. Отдельно проверены пустое состояние, загрузка/ошибка, успех и условная видимость действий.
6. По возможности просмотрено фактическое отображение в Telegram, особенно переносы кнопок, custom emoji и длинные документы. Пока эта записка основана на коде и локальных баннерах, не на живом рендеринге бота.
