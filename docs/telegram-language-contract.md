# Язык Telegram-бота

Бот определяет язык при первом обращении по `Update.message.from.language_code` или
`Update.callback_query.from.language_code`. Тег `ru` (в том числе `ru-*`) даёт `ru`;
остальные теги и отсутствие тега дают `en`. После инициализации язык меняется
командой `/language` и не перезаписывается последующими обновлениями Telegram.

## Действующий контракт lis-tm

- `TelegramDataPreferences.languageCode`: nullable `String`, значения `ru` и `en`.
  Для существующих пользователей `null` означает, что язык ещё не сохранён.
- `POST /api/telegram/user/general/init?chatId=...&languageCode=en`:
  `languageCode` — необязательный параметр. Сохранить его только при создании
  пользователя (`CREATED`). При `EXISTS` не менять выбранный язык.
- `GET /api/telegram/user/general/info?chatId=...`:
  добавить `languageCode` в ответ. Бот загружает сохранённый выбор даже без
  входящего `Update`; уведомления используют этот язык получателя.
- `PUT /api/telegram/user/general/language?chatId=...` с JSON-телом
  `{"languageCode":"ru"}`: сохранить выбранный язык, вернуть HTTP 204 без тела.
  Неизвестный код языка отклонить HTTP 400.

Для старого пользователя с `languageCode: null` бот определяет язык из первого
полученного `Update` и вызывает `PUT /language`. Если сохранение недоступно,
бот хранит определённый язык в памяти до перезапуска процесса.

Реализованы выбор и сохранение языка и подключение всего интерфейса RU/EN:
меню, формы, проверки, результаты, кнопки, общие блоки, уведомления и Excel.
После сохранения выбора описания команд обновляются для текущего чата.
Уведомления формируются на сохранённом языке получателя, включая отдельные
сообщения администраторам и участникам следования. Пользовательский контент
и произвольные тексты backend сохраняются в исходном виде.
Тексты читаются из properties через `ResourceBundle`, параметры форматируются
ICU4J; оформление и эмодзи остаются в Java. Подробнее:
[схема локализации](telegram-localization.md).
