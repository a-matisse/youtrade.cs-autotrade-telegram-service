# Предпочтения уведомлений CSFloat

Настройка общая для TelegramData: применяется ко всем его аккаунтам и параметрам. Новая сущность TelegramDataPreferences
связана с TD как 1:1, загружается из TD EAGER. По умолчанию bargainNotifications = true.

## Новые endpoints

| Клиент   | Метод | URL                                                                         | Авторизация / параметры                            |
|----------|-------|-----------------------------------------------------------------------------|----------------------------------------------------|
| Web      | POST  | /api/web/v1/user/properties/toggle/bargain-notifications                    | Authorization: Bearer <user-api>                   |
| Telegram | POST  | /api/telegram/user/properties/toggle/bargain-notifications?chatId=<chat-id> | Существующая внутренняя защита YouTradeInnerFilter |

Тело запроса не требуется. Оба входа используют FcdPropertiesService. Ответ HTTP 200 в существующем формате FCD:

```json
{
  "result": true,
  "cause": "success",
  "data": false
}
```

data — новое состояние: false означает, что уведомления выключены. Если пользователь не найден:

```json
{
  "result": false,
  "cause": "Пользователь не найден.",
  "data": null
}
```

Web использует обычную проверку Bearer; некорректный формат заголовка даёт HTTP 401. Telegram endpoint предназначен для
внутреннего клиента, не для прямого вызова из браузера.

## Изменение ответа текущих параметров

FcdParamsGetDto дополнен boolean-полем bargainNotifications. Изменённые GET: /api/web/v1/user/params (Bearer) и
/api/telegram/user/params?chatId=<chat-id> (внутренняя авторизация). Поле находится внутри data существующего
FcdDefaultDto в ответе получения текущих параметров. Это значение TD, поэтому при смене параметров оно остаётся общим.

Фронт читает поле при загрузке и отображает кнопку «Уведомления о торгах». После POST берёт новое состояние из data
только при result = true. На время запроса стоит отключать повторное нажатие. Toggle не идемпотентен:
после потери ответа следует перечитать параметры, а не автоматически повторять POST.

## Что отключается

Только CSFloat BARGAIN_CREATED и BARGAIN_FAILED. FAILED включает причины неуспешного завершения (отклонение, отмена,
истечение срока), а не только отказ продавца. BARGAIN_ACCEPTED и остальные уведомления остаются активны. Сделки,
комиссии, возвраты и история продолжают обрабатываться. Перед публикацией читается актуальный TD с preferences; уже
опубликованные в Redis сообщения не отзываются.

## Развёртывание

Выполнить flyway/20260913_telegram_data_preferences.sql в базе spring.datasource.listg (DB_HOST_SECONDARY),
предпочтительно перед запуском нового кода. SQL хранится в Git, не содержит секретов и запускается вручную; библиотека
Flyway не добавляется. Скрипт совместим с таблицей, созданной Hibernate update, и допускает повторный запуск без
изменения существующих предпочтений.

Для новых TD preferences создаются каскадно. Если у старого TD ещё нет записи, уведомления считаются включёнными; первое
переключение создаёт запись.
