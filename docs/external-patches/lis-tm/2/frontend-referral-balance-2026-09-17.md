# Реферальный баланс: изменения API для фронта

Реферальные начисления теперь отделены от основного баланса. Поле `balance` остаётся основным балансом, новое поле `referralBalance` содержит доступное реферальное вознаграждение. Суммы передаются как JSON number с точностью до центов.

## Доступ к Bargain

Публичный режим доступа настраивается на backend и не требует нового переключателя на фронте. Endpoint `POST /api/web/v1/user/buy/toggle/bargainable` сохраняется. Когда публичный доступ включён, ежечасная задача выдаёт или продлевает доступ всем пользователям, у которых его нет либо осталось меньше суток, до 30 дней от текущего момента. Это включает новых пользователей.

Публичный режим не включает `bargainable` сам и не обходит проверку доступа в endpoint: пользователь по-прежнему явно переключает режим. При выключенном публичном режиме применяется обычная проверка доступа по обороту; если доступ отозван, backend также выключает `bargainable`. Текущее состояние доступа фронт получает из существующего поля `bargainAllowed` в данных аккаунта.

## Изменённые ответы

Поле `referralBalance` добавлено во все пользовательские ответы, в которых уже возвращался основной баланс:

- данные аккаунта Web и Telegram (`FcdGeneralAccInfoDto`);
- текущие параметры Web и Telegram (`FcdParamsGetDto`);
- список параметров Web и Telegram (`FcdParamsListDto`);
- список пользователей админского API (`FcdAdminUserDto`);
- уведомления об изменении баланса (`YTBalanceNotification`).

Фронт должен показывать основной и реферальный балансы отдельно. Реферальный баланс нельзя считать частью `balance` до явного перевода.

## API пользователя

### Получить оба баланса

`GET /api/telegram/user/ref/balance?chatId=<chatId>`

```json
{
  "tdId": 42,
  "balance": 120.00,
  "referralBalance": 35.00,
  "totalReferralEarnings": 85.00,
  "totalDeposits": 100.00
}
```

`totalReferralEarnings` — сумма всех прямых реферальных вознаграждений за всё время. Она только растёт при новом начислении и не уменьшается при переводе в основной баланс или ручном выводе. Это статистика заработка, а не доступная к расходованию сумма; для доступной суммы используется `referralBalance`. Поле также возвращается существующим API реферальной информации (`FcdRefDto`).

### Перевести реферальный баланс в основной

`POST /api/telegram/user/ref/balance/transfer?chatId=<chatId>&amount=10.00&requestId=<uuid>`

Перевод выполняется один к одному, без комиссии и без бонуса за пополнение. `requestId` обязателен и служит ключом идемпотентности.

```json
{
  "requestId": "6217fdee-3278-4f5c-bb06-4f8fd121d189",
  "type": "TRANSFER",
  "status": "COMPLETED",
  "amount": 10.00,
  "networkFee": 0.00,
  "payoutAmount": 0.00,
  "balance": 130.00,
  "referralBalance": 25.00,
  "createdAt": "2026-09-17T20:30:00",
  "updatedAt": "2026-09-17T20:30:00",
  "completedAt": "2026-09-17T20:30:00"
}
```

Время передаётся в UTC. `createdAt` — создание операции, `updatedAt` — последнее изменение, `completedAt` — окончательное завершение. Сейчас перевод и ручной вывод завершаются сразу, поэтому значения совпадают. В будущей асинхронной выплате `completedAt` может быть `null` до подтверждения платёжной системы.

## API вывода для администратора

`POST /api/telegram/admin/referral-balance/withdraw`

Параметры:

- `tdId` — обязателен;
- `amount` — необязателен; без него резервируется весь реферальный баланс;
- `networkFee` — необязателен; комиссия задаётся только целым количеством долларов, без центов, значение по умолчанию — `$1`;
- `requestId` — обязательный UUID для идемпотентности.

Это единственный endpoint ручного вывода. Он сразу списывает `amount` с реферального баланса и возвращает операцию со статусом `COMPLETED`; промежуточного резервирования, подтверждения и отмены нет. Ответ содержит `amount` как списанную сумму и `payoutAmount = amount - networkFee` — эту сумму оператор отправляет пользователю вручную. При отсутствии `amount` реферальный баланс обнуляется полностью. Повторный вызов с тем же `requestId` возвращает сохранённый результат без повторного списания.

## Правила начисления

- личными пополнениями считаются `HELEKET` и `TELEGRAM` (Telegram Stars);
- только личное пополнение получает пользовательский бонус и увеличивает `totalDeposits`;
- вознаграждение начисляется только владельцу непосредственно использованного реферального кода;
- реферальное вознаграждение поступает в `referralBalance`, не получает бонус пополнения и не запускает следующую реферальную выплату по цепочке;
- `MANUAL`, `REF` и `INTERNAL` не считаются личными пополнениями.

## Совместимость фронта

Во время поэтапного развёртывания отсутствующее `referralBalance` следует трактовать как `0`. После POST-операций состояние балансов нужно брать из ответа; повторять запрос с новым `requestId` при неопределённом результате нельзя.
