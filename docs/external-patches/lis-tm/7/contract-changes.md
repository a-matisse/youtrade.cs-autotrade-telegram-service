# Изменения контрактов Y.CS

Изменения для web и Telegram при подготовке кабинета и публичной ленты. Форматы
запросов и ответов описаны в связанных документах.

## Авторизация и сессии

| Изменение | Что получает потребитель |
| --- | --- |
| `GET /api/web/v1/auth/telegram` | Браузерный вход через Telegram OIDC. Backend ставит временную cookie и возвращает 302 в Telegram со scope `openid profile telegram:bot_access` |
| `GET /api/web/v1/auth/telegram/callback` | Проверяет state, PKCE и подписанный ID token. При успехе ставит refresh-cookie и возвращает 302 на `/auth/callback`. При ожидаемом отказе возвращает туда же с `error=telegram_login_failed\|access_denied\|login_expired\|temporarily_unavailable` |
| `POST /api/web/v1/auth/refresh` | Принимает cookie и `Origin` сайта. Возвращает `accessToken`, `tokenType` и `expiresIn`, заменяет пару токенов. При ошибке отвечает HTTP-статусом |
| `GET /api/web/v1/auth/me` | Принимает Bearer JWT или API-ключ. Ответ содержит `id`, `telegramId` и `botLinked`. `botLinked` отражает наличие Telegram ID |
| `POST /api/web/v1/auth/logout` | По Bearer JWT отзывает текущую web-сессию и очищает refresh-cookie, при успехе отвечает 204 |
| Первый и повторный вход | Новый пользователь получает стандартный аккаунт Y.CS. Существующий пользователь определяется по проверенному Telegram ID. Профиль заполняется при первом успешном входе и сохраняет ручные изменения при повторном |

На успешном callback фронт вызывает refresh, затем `me` и профиль. При наличии
`error` он возвращает пользователя на экран входа, показывает сообщение по коду
и пропускает refresh. Access-токен действует час, refresh-сессия — до 30 дней
с момента входа. Входы с разных устройств имеют отдельные сессии.

Реальный вход подтверждён пользователем после исправления загрузки JWKS в gzip
(`08013418`). Запрос `telegram:bot_access` проверен на сервере. Восстановление
сессии, выход и доставку сообщений ботом отслеживаем отдельно.
[Интеграция для фронта](web-auth-frontend.md) · [Настройка и диагностика](web-auth.md) · [План проверок](user-account-next-update-plan.md).

## Профиль и аватарка

Для чтения и изменения профиля используется Bearer JWT или API-ключ.
Владелец определяется по авторизации, а изменение отправляется с версией
полученного профиля.

| Метод и путь | Контракт |
| --- | --- |
| `GET /api/web/v1/user/profile` | Возвращает внутренний ID, представление профиля, `avatar`, `version` и даты. 404 означает, что профиль ещё не инициализирован |
| `PUT /api/web/v1/user/profile` | Сохраняет `login`, `nickname`, `firstName`, `lastName` и `avatarSource`. При устаревшей `version` отвечает 409 |
| `POST /api/web/v1/user/profile/avatar` | Multipart с `file` и `version`. Загружает и выбирает аватарку. Возвращает 201 с обновлённым профилем |
| `DELETE /api/web/v1/user/profile/avatar?version=…` | Удаляет выбранную пользователем загруженную аватарку, переключает на `DEFAULT` и возвращает обновлённый профиль |
| `GET /api/web/v1/user/profile/avatar/file/{imageId}` | Выдаёт PNG по подписанному адресу из `avatar.url`. Фронт использует возвращённый URL целиком |

`avatar.source` принимает `TELEGRAM`, `DEFAULT` или `UPLOADED`.
Поле `urlExpiresAt` помогает вовремя обновить подписанный URL.
`login` и `nickname` — отображаемые поля, ключ пользователя — `id`.
[Поля, ограничения и ошибки профиля](web-auth-frontend.md#профиль-пользователя).

## Публичный API

| Метод и путь | Что изменилось |
| --- | --- |
| `GET /api/web/v1/overview/operations` | Новая открытая лента. Возвращает `operations` и `asOf`, до 100 покупок и продаж в одном списке от новых к старым. Поля строки — `id`, `type`, `itemName`, `imageUrl`, `market`, `amount`, `currency`, `occurredAt`. Кеш 30 секунд. При совпавшем `If-None-Match` возвращается 304 |
| `GET /api/web/v1/steam/currency/history` | Открытая история курса. Обязательные `from_seconds` и `until_seconds`, необязательный `currency`. Возвращает точки `{currency, rate, time}` для интервала `[from_seconds, until_seconds)` до трёх суток. Некорректный интервал — 400 |
| `GET /api/web/v1/overview` | В публичном тарифе Balance Market доступна резервная ставка. При недоступности свежего расчёта `balanceMarketPricing.rateUpdatedAt` равно `null`, фронт показывает возвращённую `totalFeePercent` |
| `GET /api/web/v1/overview/documents` | Публичное чтение четырёх документов с локалью `ru`, `en` или `ka`. История прежних P2P API вынесена в архив |

Для карточки операции достаточно `imageUrl`, `amount`, `currency`, `type`.
Для покупки `amount` означает цену покупки, для продажи — зачисление площадки
до вывода. Идентификатор карточки подходит для обновления ленты и позиции
прокрутки. После запуска backend требуется маршрут ленты в Nginx.
[Форматы ответов и маршрут выкладки](landing-api.md).

## Схема и выкладка

Профиль и метаданные аватара добавлены отдельными Flyway-миграциями. Для ленты
в рабочей копии подготовлена миграция трёх индексов времени, а её контракт
проверен локально. Production-выкладка ленты ещё не подтверждена.
[База и порядок миграций](../database-migrations.md).

Разделение платформенного пользователя и Telegram-привязки, дополнительные
способы входа и финансовый кабинет находятся на стадии проектирования.
[План и аудит источников](user-account-next-update-plan.md).
