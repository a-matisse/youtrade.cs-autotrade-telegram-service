# Overview API для лендинга

## Endpoint

```http
GET /api/web/v1/overview
```

Endpoint открыт без `chatId` и API-ключа. Backend кеширует агрегированную часть на пять минут и рассчитывает публичный тариф Balance Market при выдаче ответа. HTTP-ответ имеет `Cache-Control: no-store`.

## Состав ответа

- `brand` — `Y.CS`.
- `telegramBotUrl` — ссылка CTA из `TELEGRAM_BOT_URL`.
- `pricing` — актуальные цены покупки, bargain-покупки, продажи и worker.
- `balanceMarketPricing` — публичный тариф Balance Market. `rateUpdatedAt=null` обозначает резервный тариф при отсутствии свежей ставки.
- `statistics` — агрегированная статистика без пользовательских данных.
- `generatedAt` — время формирования ответа.

`statistics.daily` всегда содержит 30 календарных точек, включая дни без продаж. Это позволяет строить график без дополнения дат на фронте.

Финансовые поля рассчитываются так:

```text
cost = Σ(boughtFor × (2 − purchaseMarket.topUpFee))
profitAfterWithdrawalFee = revenue × (1 − feeRate) − cost
```

`revenue` — фактическая сумма завершённых продаж, а `cost` — себестоимость проданных предметов с учётом комиссии пополнения площадки покупки. Все денежные значения выражены в USD и округлены до двух знаков.

## Старый endpoint цен

`GET /api/telegram/no-role/pay?chatId=...` возвращает цены, но находится под внутренним interceptor для `/api/telegram/**`. Для лендинга следует использовать `pricing` из overview.

## Лента курсов Steam

```http
GET /api/web/v1/steam/currency
```

Это отдельный открытый endpoint для верхнего ticker-а. Ответ отсортирован по `currency` и публично кэшируется пять минут.

```json
[
  {
    "currency": "RUB",
    "rate": 92.45,
    "time": 1789725600,
    "sourceItemname": "Example item",
    "sourcePriceTime": 1789725300,
    "source": "STEAM"
  }
]
```

Для основной ленты достаточно `currency` и `rate`. Остальные поля можно использовать во всплывающей подсказке с источником и актуальностью расчёта. Если endpoint временно вернул пустой массив, ленту следует скрыть без ошибки всей страницы.

## История курсов Steam

```http
GET /api/web/v1/steam/currency/history?from_seconds=1795129200&until_seconds=1795132800&currency=RUB
```

Открытый endpoint. Обязательные границы в Unix-секундах задают интервал
`[from_seconds, until_seconds)` продолжительностью до трёх суток включительно.
Необязательный `currency` фильтрует валюту без учёта регистра. Пустой фильтр,
отрицательная нижняя граница, перепутанные или равные границы и окно больше
259 200 секунд возвращают HTTP 400.

```json
[
  {"currency": "RUB", "rate": 92.45, "time": 1795131000}
]
```

`rate` — число единиц валюты за 1 USD, `time` — Unix-секунды. Точки отсортированы
по времени и валюте. При отсутствии наблюдений возвращается `[]`.
`Cache-Control` — `max-age=300, public`.

## Крупнейшие сделки дня

```http
GET /api/web/v1/overview/deals
```

Открытый endpoint возвращает до трёх наиболее прибыльных завершённых сделок за последние 24 часа. Сделки отбираются и сортируются по прибыли после 5% комиссии вывода: `revenue × 0.95 − cost`. В ответе каждый визуальный скин встречается один раз: при проверке уникальности не учитываются wear, `StatTrak™`/`StatTrack TM`, `Souvenir` и символ `★`; среди дублей сохраняется самая прибыльная сделка. Пользовательские, аккаунтные и токенные идентификаторы не возвращаются. Ответ кэшируется backend, браузером или CDN на пять минут.

```json
[
  {
    "itemName": "Example item",
    "imageUrl": "https://cdn.example/example-item.png",
    "soldAt": "2026-09-19T10:00:00",
    "source": "CSFLOAT",
    "destination": "MARKET_CSGO",
    "cost": 101.10,
    "revenue": 140.00,
    "profit": 38.90
  }
]
```

- `cost` — стоимость покупки с комиссией пополнения источника;
- `imageUrl` — ссылка на изображение предмета из внутреннего справочника; может быть `null`, если изображения нет;
- `revenue` — фактически полученная после продажи сумма до сценарной комиссии вывода;
- `profit` — прибыль до сценарной комиссии вывода: `revenue - cost`; это исходное значение для расчётов фронта, а рейтинг сделок уже учитывает комиссию вывода 5%.

Порядок уже задан backend по убыванию прибыли после 5% комиссии вывода. Если сделок за день меньше трёх, массив будет короче; если сделок нет — пустым.

## Последние операции Y.CS

```http
GET /api/web/v1/overview/operations
```

Открытый endpoint без авторизации и параметров. Возвращает **до 100 операций всего**,
покупки и продажи вместе, от новых к старым. Это операции текущей автоторговли
на внешних площадках, учтённые Y.CS; активные торги, контр-офферы и выставления
предметов не считаются исполненными операциями.

```json
{
  "operations": [
    {
      "id": "fd0810b0e742995e723c34b00750f2550414e1aebdd482797212e80918873b12-1",
      "type": "BUY",
      "itemName": "★ Specialist Gloves | Blackbook (Field-Tested)",
      "imageUrl": "https://cdn.example/gloves.png",
      "market": "CSFLOAT",
      "amount": 195.89,
      "currency": "USD",
      "occurredAt": "2026-11-20T17:40:24.329989Z"
    },
    {
      "id": "996ced900e8a635cbf31c60c5f360d451e50cbea7ab54dd2a60fc93b33f3106f-1",
      "type": "SELL",
      "itemName": "★ Hand Wraps | Desert Shamagh (Field-Tested)",
      "imageUrl": null,
      "market": "MARKET_CSGO",
      "amount": 35.23,
      "currency": "USD",
      "occurredAt": "2026-11-20T17:29:40Z"
    }
  ],
  "asOf": "2026-11-20T17:42:54Z"
}
```

| Поле | Значение / отображение |
| --- | --- |
| `operations[].id` | Публичный ключ карточки для обновления списка и сохранения позиции прокрутки. Сохраняется при обновлении снимка и переносе покупки в историю продаж, пока данные самой операции совпадают |
| `operations[].type` | `BUY` — «Покупка», `SELL` — «Продажа» |
| `itemName` | Полное название, включая wear и StatTrak/Souvenir; одинаковые предметы в разных операциях сохраняются |
| `imageUrl` | Изображение из справочника; при `null` — заглушка |
| `market` | Площадка конкретной операции, например `CSFLOAT`, `MARKET_CSGO` |
| `amount` | Для BUY — записанная цена покупки предмета. Для SELL — фактическая сумма зачисления после комиссии продажи площадки, до вывода. Это разные денежные потоки, не два края стакана |
| `currency` | `USD`; суммы округлены до двух знаков. Комиссия Y.CS, пополнение и вывод дополнительно в сумму не включаются |
| `occurredAt` | Сохранённое время операции в UTC, ISO 8601 с `Z`; для покупки это время учёта покупки Y.CS, которое может отличаться от времени запроса или исполнения на площадке |
| `asOf` | Время формирования полученного снимка ленты |

В одной завершённой покупке с последующей продажей есть две операции, а не одна.
Физический предмет из `youtrade_purchased_item` при продаже переносится в
`youtrade_sold_item`; покупка также читается из этой таблицы и продолжает попадать
в ленту по исходному времени. Отсутствующие/неположительные/нечисловые цены,
пустые имена и будущие времена операции отфильтрованы. Неизвестная цена не заменяется
оценкой fuzzy. Ответ содержит только публичные данные операции. Ключ карточки
формируется из этих данных, а одинаковые по всем полям операции получают разные ключи.

На backend один общий снимок на **30 секунд** в памяти каждого экземпляра приложения.
Одновременные посетители используют одну загрузку снимка. На промахе выполняются
один ограниченный JPA-запрос операций и один пакетный JPA-запрос изображений;
на попадании в кеш запросов репозиториев нет. HTTP `Cache-Control: no-cache, public`
включает перепроверку снимка через `ETag`. При совпавшем `If-None-Match` сервер
возвращает `304 Not Modified` без тела. При появлении или отмене операции, смене
порядка или изображения клиент получает `200 OK` с новым снимком. Один лишь
пересчёт `asOf` не меняет `ETag`.

Это текущее состояние учёта, а не неизменяемый журнал окончательных расчётов:
поздняя отмена покупки удаляет её из текущих предметов; отменённая продажа удаляется
из продаж и возвращает предмет в покупки. После обновления снимка такие операции
исчезают из ленты. Пока отмена не обнаружена системой, она не может быть отражена
в API. До 100 — верхний предел, пустая история возвращает `operations: []`.
При сбое источника возвращается ошибка 5xx, а не фиктивная пустая история.

### Отображение ленты на экране входа

Лента видна до входа в систему. На широком экране она находится в левой части
лендинга рядом с формой входа. Это обновляемый вертикальный список до 100 операций:
новые покупки и продажи сверху, прокрутка вниз показывает более старые.

В карточке показываем изображение предмета (`imageUrl`), а рядом — сумму с валютой
(`amount`, `currency`) и направление (`type`: «Покупка» или «Продажа»).

Фронт может запрашивать ленту каждые 15–30 секунд, пока страница видима.
При обновлении используем `id` как ключ строки, чтобы сохранить позицию прокрутки.
Если клиент вручную передаёт `If-None-Match`, при `304` он сохраняет прежний список.

### Выкладка

Обновить `youtrade.cs-lis-tm`. Новая Flyway-миграция
`V20261120_03__public_operation_feed_indexes.sql` создаёт индексы по временам
текущих покупок, покупок в проданных позициях и продаж. Применяется автоматически
при запуске с включённым Flyway; рабочая схема в ходе разработки не менялась.

В текущем Nginx-шаблоне соседнего frontend-проекта разрешены точные адреса overview,
deals и documents. Для нового адреса добавить отдельный маршрут и проверить
`nginx -t` перед reload:

```nginx
location = /api/web/v1/overview/operations {
    proxy_pass http://127.0.0.1:21488;
    include proxy_params;
}
```

Проверка после выкладки:

```bash
curl -fsS https://youtradecs.xyz/api/web/v1/overview/operations
```

В этой задаче frontend и рабочий Nginx не изменялись.

## Документы Y.CS

```http
GET /api/web/v1/overview/documents
```

Открытый endpoint без `Authorization` и `X-Service-Key`. Необязательный параметр `locale=ru|en|ka` выбирает язык; по умолчанию `ru`. Возвращает общие условия Y.CS, условия оплаты, правила возврата и политику персональных данных. Черновик реферальных условий в API не выдаётся. Для четырёх документов доступны переводы на английский и грузинский. Поля `version`, `locale` и `contentHash` идентифицируют конкретный текст. Переводы имеют суффиксы версии `-en` и `-ka`. `published=true` для всех четырёх документов. Чтение выполняется из файлов через `ServiceDocumentService`, без обращения к БД. Получение документов не означает их принятие.
