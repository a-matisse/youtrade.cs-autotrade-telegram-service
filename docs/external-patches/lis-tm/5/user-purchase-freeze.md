# Пользовательская заморозка покупок аккаунта

Пользовательская заморозка хранится в `youtrade_market_token.user_purchase_unfreeze_at`.
Она не меняет системные `frozen_at`, `unfreeze_at` и `freeze_reason`.
Обе причины независимо запрещают новые покупки с аккаунта.

`PUT /api/web/v1/user/accounts/v2/buyer/{steamTokenId}/purchase-freeze`

Заголовок: `Authorization: Bearer <user-api-key>`.
`steamTokenId` — ID Steam-аккаунта из страницы аккаунтов, не ID ключа покупки.

```json
{"days":7}
```

`days` — целое число от 0 до 3650. Положительное значение устанавливает новый
срок от момента запроса. `{"days":0}` снимает только пользовательскую
заморозку. Если системная заморозка ещё действует, покупки не возобновятся.
Успех — `204`; неверный срок — `400`; отсутствующий или чужой аккаунт
покупки — `404`.

После записи в БД замороженный ключ удаляется из текущей карты автопокупки.
При `days: 0` обновление карты запускается сразу; при истечении срока — во время
планового обновления карты (каждые две минуты). Уже отправленные запросы
на покупку не отменяются.

В `GET /api/web/v1/user/accounts/v2` у каждого аккаунта в `buyBalance`
возвращаются `userPurchaseFrozen`, `userPurchaseUnfreezeAt`,
`systemPurchaseFrozen` и существующие `accountFrozen`, `accountUnfreezeAt`.
`accountFrozen` сохранён для совместимости и отражает системную заморозку.
Поля заморозки находятся в `buyBalance`; если ключ покупки отсутствует,
`buyBalance` равен `null`.

## Отображение в меню аккаунта

В меню аккаунта нужно явно сообщать пользователю, почему покупки остановлены:

- При `userPurchaseFrozen: true` показывать «Покупки приостановлены вами до
  <дата и время>» на основе `userPurchaseUnfreezeAt` и действие «Возобновить
  покупки». Это действие отправляет `{"days":0}`.
- При `systemPurchaseFrozen: true` отдельно показывать «Покупки временно
  приостановлены системой до <дата и время>» на основе `accountUnfreezeAt`.
  Пользовательская кнопка не должна снимать или скрывать эту причину.
- Если активны обе заморозки, показывать обе. После снятия пользовательской
  заморозки не обещать возобновление покупок, пока действует системная.

Для установки пользовательской заморозки меню должно передавать ID аккаунта
и выбранный срок в днях в ту же `PUT`-ручку. После ответа следует обновить
данные аккаунта, чтобы показать актуальные состояния.

Перед запуском применить [`flyway/20261008_user_purchase_freeze.sql`](../../flyway/20261008_user_purchase_freeze.sql)
к `DB_HOST_SECONDARY` (`spring.datasource.listg`).
