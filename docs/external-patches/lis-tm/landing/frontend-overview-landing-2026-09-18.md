# Публичный overview для лендинга Y.CS

Использовать один запрос:

```http
GET /api/web/v1/overview
```

Авторизация и `chatId` не требуются. Ответ кэшируется backend, браузером или CDN до пяти минут.

## Что выводить

- `telegramBotUrl` — основная CTA-кнопка.
- `pricing.buySubPrices` — тарифы автоматической покупки.
- `pricing.bargainBuySubPrices` — тарифы bargain-покупки.
- `pricing.sellSubPrices` — тарифы автоматической продажи.
- `pricing.workerPriceData` — стоимость worker.
- `statistics.purchases` — количество покупок.
- `statistics.purchaseVolume` — оборот покупок в USD.
- `statistics.sales` — число завершённых продаж.
- `statistics.cost` — себестоимость завершённых продаж с комиссией пополнения в USD.
- `statistics.revenue` — объём завершённых продаж в USD.

## Верхняя лента курсов Steam

Ленту загружать отдельным запросом:

```http
GET /api/web/v1/steam/currency
```

Каждая запись содержит `currency`, `rate`, `time`, `sourceItemname`, `sourcePriceTime` и `source`. Для бегущей строки показывать валюту и курс; источник и время можно вынести в tooltip. Ответ уже отсортирован по валюте и кэшируется на пять минут. При пустом массиве скрыть только ленту.

## График

Массив `statistics.daily` содержит последние 30 дней, включая нулевые дни. Построить три линии:

- без комиссии: `revenue - cost`;
- комиссия 3%: `revenue * 0.97 - cost`;
- комиссия 5%: `revenue * 0.95 - cost`.

Backend отдаёт исходные `revenue` и `cost`. `cost` уже включает комиссию пополнения площадки покупки. Прибыль и процентные сценарии рассчитывает фронт, поэтому можно добавлять другие ставки без изменения API. Комиссию вывода следует применять к `revenue`, затем вычитать `cost`.

Для общей статистики использовать `cost` вместо `purchaseVolume`: последний включает также ещё не проданные покупки.

## Секции лендинга

Рекомендуемый порядок: первый экран, преимущества, принцип работы, тарифы, статистика, сравнение комиссий, FAQ, переход в Telegram. Готовые формулировки преимуществ находятся в `docs/landing/positioning.md`.

## Блок крупнейших сделок дня

Загрузить отдельно:

```http
GET /api/web/v1/overview/deals
```

Показать до трёх карточек в порядке ответа. Для каждой сделки вывести `imageUrl`, предмет, площадки, время, `cost`, `revenue` и три варианта прибыли. Если `imageUrl` равен `null`, использовать локальную заглушку:

- до комиссии вывода: `profit` или `revenue - cost`;
- при комиссии 3%: `revenue * 0.97 - cost`;
- при комиссии 5%: `revenue * 0.95 - cost`.

Комиссия уменьшает `revenue`, после чего вычитается неизменный `cost`. Нельзя уменьшать готовое значение `profit` на 3% или 5%, поскольку это даст математически неверный результат.

Рекомендуемые подписи: «До комиссии вывода», «Вывод 3%», «Вывод 5%». Не связывать карточки с пользователем: API намеренно не содержит `userId`, `chatId`, Steam ID, токен или имя аккаунта. При пустом массиве скрыть блок целиком.
