# Уведомления о блокировке и доступе Bargain

Патч для фронт-бота. Backend публикует события в существующий Redis stream `notification-stream`, поле записи `payload` содержит JSON. Обработчику уведомлений нужны четыре новых значения `type`:

| Тип | Когда приходит | Текст для пользователя |
| --- | --- | --- |
| `USER_BLOCKED` | Администратор установил или заменил блокировку | Сервис приостановлен до `until`; показать `reason` и предложение обратиться в поддержку. |
| `USER_UNBLOCKED` | Администратор снял блокировку или её срок истёк | Обслуживание восстановлено; показать `reason`. `until` — прежний срок блокировки. |
| `BARGAIN_ACCESS_GRANTED` | Разрешение выдано или продлено вручную, по пополнениям, обороту либо публичному режиму | Доступ к Bargain действует до `until`; показать `reason`. |
| `BARGAIN_ACCESS_REVOKED` | Разрешение истекло и не было продлено по текущим правилам | Доступ к Bargain прекращён; показать `reason`. `until` — прежний срок доступа. |

Пример `payload`:

```json
{
  "product": "YOUTRADE_PRO",
  "type": "USER_BLOCKED",
  "tdId": 123,
  "chatId": 456,
  "effectiveAt": "2026-09-23T12:00:00",
  "until": "2026-10-23T12:00:00",
  "reason": "Проверка безопасности"
}
```

`effectiveAt` и `until` — ISO local date-time в UTC. Для событий снятия/отзыва `until` показывает прежний срок, а не дату, до которой сохраняется новое состояние. У всех четырёх событий есть причина. Бот должен отображать её как текст, экранируя HTML/Markdown пользовательского ввода. `USER_BLOCKED` не закрывает доступ к `initUser` и `viewAccInfo`: пользователь может посмотреть кабинет и остаток средств.

Административные методы под `X-Service-Key`:

- `POST /api/debug/users/{tdId}/block?days=7&reason=...` — установить срок; отсутствие `days` означает 30 лет. Повторный вызов заменяет текущую блокировку.
- `DELETE /api/debug/users/{tdId}/block?reason=...` — снять блокировку.
- `GET /api/debug/users/{tdId}/blocks?limit=100` — периоды блокировки, новые записи первыми. Каждый содержит причину, срок, дату снятия и причину снятия.
- `GET /api/debug/users/{tdId}/actions?limit=100` — общий журнал действий, новые записи первыми. Каждая содержит `actionType` (одно из четырёх значений выше), `occurredAt`, `validUntil` и `reason`. Для снятия блокировки и отзыва Bargain `validUntil` — прежний срок.

Каждое событие записывается в журнал действий; уведомление отправляется после коммита изменения в БД. Обработчик Redis находится в проекте бота; для доставки пользователю нужно добавить обработку новых `type` там. Пользовательскому фронту административные методы с `X-Service-Key` вызывать не нужно: они приведены для контекста и проверки событий.

Для развёртывания backend применить к `spring.datasource.listg` миграции `V20260923_01`, `V20260923_02`, `V20260923_03`, `V20260923_04` по порядку. Миграция `04` переименовывает таблицу периодов блокировки; API и JSON уведомлений от этого не меняются.
