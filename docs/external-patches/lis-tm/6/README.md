# Balance Market: вывод баланса Market.CS в USDT

Статус: новая спецификация от 12.10.2026. Это проектирование, а не описание уже работающего вывода. Внешние API будут поступать поэтапно; их отсутствие сейчас отмечено как ToDo. Старые документы P2P сохранены в [архиве](legacy-p2p-marketcs/README.md) и не определяют новый продукт.

**С чего начать:** [этапы запуска и действия владельца](LAUNCH.md). Для продолжения разработки есть [подробный ToDo](TODO.md), а для сайта и Telegram-бота — [контракт интерфейсов](FRONTEND.md). Основные запросы RedBalance описаны; неизвестные ответы и ошибки клиент сохраняет для последующего уточнения.

Внешний `youtrade.cs-market.cs-bot` участвует только в начале принятой заявки: через Playwright выпускает актуальный API-ключ управляющего аккаунта Market.CS и в общей БД атомарно сохраняет ключ открытым текстом вместе с переходом заявки в `API_KEY_READY`. HTTP-вызова Y.CS для передачи ключа нет. Затем Y.CS очищает прежний баланс этого аккаунта, переводит средства пользователя и продолжает работу с RedBalance. [Требования для userbot](marketapp-key-provisioning/README.md). Один экземпляр `rb_session` обслуживает только один активный денежный процесс; другие заявки могут ждать в очереди, но не принимаются к исполнению до освобождения сессии.

## Модель

Пользователь Y.CS подаёт заявку на вывод баланса выбранного аккаунта Market.CS. Y.CS сам исполняет перевод и организует выплату USDT через выбранную внешнюю площадку; первая интеграция — RedBalance. Выбор площадки и управляющих аккаунтов принадлежит Y.CS, продавец не получает собственного кабинета или backend в нашей системе. Список «статических продавцов» не нужен: подключаемые площадки и аккаунты должны быть управляемыми данными, а интеграции — отдельными адаптерами. Отдельной P2P-сделки между пользователем и оператором больше нет.

Для денежных маршрутов предусмотрены две таблицы: [управляющие аккаунты и аккаунты остатков](data-model.md). Каждая запись содержит enum площадки, поэтому модель допускает будущие источники. В первой версии пользователь выводит баланс только Market.CS, а управляющий и остаточный аккаунты выбираются автоматически по доступности. Их роли строго раздельны. Фактические шаги Market.CS и RedBalance ожидают схем API.

Ставка надбавки Y.CS одна для всей новой функции: `youtrade.balance-market.markup-rate` в `src/main/resources/application.yaml`. Сейчас это 0,2%. Старые `fee.rate` и операторская комиссия из архивной P2P-спецификации не используются. Направление применения ставки к курсу и точное округление ждут ответа владельца продукта; до фиксации формулы нельзя показывать окончательную сумму или принимать подтверждение. Конфигурация уже добавлена, её чтение будущим сервисом ещё не реализовано.

## Пользовательский путь

Весь путь ниже должен работать через кнопки и экраны Telegram-бота, а также через сайт. Telegram-бот получает данные через собственный Telegram API Y.CS; сайт через web API. Расчёт и состояние заявки общие для обоих каналов.

1. «Вывести деньги»: выбрать свой аккаунт Market.CS и сумму к списанию в USD Market.CS.
2. Ввести платёжный пароль Market.CS для выбранного аккаунта. В собственный API Y.CS он передаётся в JSON body, без query-параметров. Внешний Market.CS `money-send` требует `pay_pass` в URL; этот URL нельзя записывать в события, логи или трассировки. Пароль не хранится в постоянных клиентских хранилищах.
3. В расширяемом меню нажать кнопку способа вывода «USDT TRC-20», указать адрес и отдельно подтвердить показанные способ и полный адрес. В первой версии enum способов вывода содержит только `USDT_TRC20`; другие способы добавляются позже без переделки меню.
4. Увидеть последний сохранённый курс продавца, курс Y.CS с надбавкой, исходную сумму и предварительную расчётную выплату. Курс обновляется каждые 30 секунд. При создании заявки его возраст не должен превышать 1 минуту, а последнее обновление должно быть успешным; сохранить в БД значение и время обновления. Снимок котировки не меняется при фоновых обновлениях; фактическая выплата определяется ответом RedBalance `check` после поступления денег и сохраняется отдельно.
5. Получить ID заявки и статус `QUEUED`: заявка в очереди, исполнение может занять время. Пока worker не принял её к исполнению, пользователь может отменить заявку; через 15 минут ожидания она отменится автоматически. После принятия API сообщает этапы и итог; Redis Stream доставляет уведомления, а состояние восстанавливается из БД.

До подтверждения показывать предупреждение: перевод по неверному адресу или в неверной сети может быть необратим; пользователь обязан сверить весь адрес и сеть. Формулировку итогового согласия и юридические условия согласовать отдельно.

В боте обязательны кнопки входа в вывод, выбора аккаунта и способа «USDT TRC-20», просмотра котировки, подтверждения заявки, просмотра статуса и отмены до принятия. Платёжный пароль вводится через защищённую форму, а не сообщением в Telegram-чате. Изменение интерфейсов сайта и бота требует отдельного согласования с владельцем проекта и в этой документационной задаче не выполняется.
